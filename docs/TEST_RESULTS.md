## Recovery workflow added in this continuation

- Platform payment attempts are persisted before the STK network request, with authenticated initiator, intended KES amount/reference, timestamps, state history, and provider request identifiers when available. Definite pre-STK/auth/rejection errors are distinguished from transport or unknown outcomes. An interrupted `IN_PROGRESS` attempt becomes `REQUIRES_REVIEW` after 45 seconds; it remains pending and is never automatically resubmitted.
- Where `CheckoutRequestID` is durably stored, authenticated reconciliation can query Daraja with bounded retry/backoff. The supported query needs the checkout ID and shortcode; no documented lookup by account reference or merchant request ID is implemented. A missing checkout ID stays pending and returns an explicit review instruction.
- Platform manual review is restricted to platform administrators and eligible self-STK attempts. It requires provider statement/portal evidence reference, exact KES amount, normalized payer, shortcode, STK account reference, provider receipt and transaction time, plus a substantive reason. Compare-and-set protects concurrent reviewers; receipt uniqueness prevents reuse. Stored confirmation source remains `manual_review` until matching provider callback evidence arrives. Participant responses omit private evidence fields.
- School staff/admin review is tenant-scoped, exact-amount and receipt/reference checked, and auditable. Its source is also labeled `manual_review`; parent/staff response serialization does not expose private evidence details. Receipts label manual review separately from provider callback verification.
